# Feature documentation guidance

This directory's first-pass product inventory is indexed in [FEATURES.md](FEATURES.md). Project AGENTS.md files retain their architecture and development rules.

- Consult the owning project's FEATURES.md and implementation before recommending features; a missing documentation mention is not evidence of missing functionality.
- Keep unaccepted ideas in the owning project's plan/FEATURE-PROPOSALS.md. Move a proposal into plan/FEATURE-IMPROVEMENTS.md only after explicit acceptance, preserving its ID and recording the decision and scope.
- Follow the [catalog maintenance and planning workflow](FEATURES.md#planning-workflow). Update the inventory when capabilities change, and distinguish source presence, validated behavior and confirmed released availability.
- Root plan files index cross-project work. Give each cross-project proposal one canonical project owner and link from participants.
- Do not treat priority, this analysis, historical PLAN.md files or approval to document the repository as product-feature acceptance.
