## Acceptance record

After explicit acceptance of a bounded scope, move the complete proposal here under its original `AZURE-###` ID and record:

- Accepting maintainer, date and decision/request reference.
- Customer outcome, agreed scope/exclusions, canonical owner and participants.
- Source baseline, implementation plan, compatibility/migration and acceptance criteria.
- Status: Accepted → In progress → Implemented → Released, tracked separately.
- Actual validation: SDK versions, target runtimes, fakes versus Azurite versus real Azure, resource/IAM scope and any native Speech/codec requirements.
- Documentation/examples and implementation revision; published version/tag/release-note evidence only when confirmed.

Leave a decision link in proposals and update the inventory when behavior changes. Participants link to the canonical owner; deferred/rejected ideas retain a reason.
