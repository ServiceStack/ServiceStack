## Package and ownership

- [ServiceStack.Azure.csproj](ServiceStack.Azure.csproj) targets `net472;net6.0;net8.0;net10.0`, referencing ServiceStack, Client, Common, Interfaces and Text. The inspected package versions are Azure.Data.Tables 12.13.0, Azure.Storage.Blobs 12.30.0, Azure.Storage.Common 12.29.0, Azure.Messaging.ServiceBus 7.21.0 and Microsoft.CognitiveServices.Speech 1.52.0. Some targets add LINQ/JSON dependencies.
- This package owns block/append Blob VFS, Table cache, Service Bus MQ and AzureSpeechToText. The speech provider's `ServiceStack.AI` namespace does not move its implementation to the ServiceStack.AI project.
- Service Bus implementation uses queues and ordinary queue processors. The inspected high-level adapter does not implement topic/subscription or session-processor topology simply because the underlying Azure service supports it.
- Blob providers accept an application-created BlobContainerClient, enabling SDK authentication/options chosen by the caller. Table cache and MQ public constructors inspected here accept connection strings and construct their own clients. A modern SDK dependency alone does not establish TokenCredential/managed-identity configuration across every adapter.
- FilesUploadFeature, generic MQ handling, cache/VFS/speech interfaces and application authorization have separate owners. Azure hosting, Azure Redis, Cosmos DB, Azure OpenAI, Key Vault and deployment recipes are not additional provider implementations established by this package's name.

## Validation and reproduced concerns

On 2026-11-11 the library built for all four target frameworks with existing warnings. The repository test project could not be built from its stale dependency assets; refreshing from the local NuGet cache was blocked by an unavailable Microsoft.Azure.KeyVault.Core package. No test-project dependency/source changes were made. An isolated net10.0 runner referencing the built library directly executed all three existing AzureSecurityTests methods successfully and used scripted SDK subclasses for focused observations. Those direct method calls are not a successful run of the full NUnit suite.

The runner reproduced these eight concern areas:

1. An expired cache snapshot triggered a second read, then wildcard-ETag deletion of a scripted fresh replacement.
2. AddAsync returned false for a physically present expired row, without reclaiming it.
3. ReplaceAsync accepted an expired row and used wildcard ETag.
4. `GetDirectory("a/b").GetAllMatchingFiles("*", 1)` omitted its direct file because depth was measured from the container root.
5. Block-blob directory GetEnumerator threw NotImplementedException. The append implementation has the same source stub; it was not separately probed.
6. The Service Bus worker replaced a custom message Meta dictionary with lock/queue metadata.
7. A real generic MessageHandler with a scripted business failure and failed DLQ publish returned to the worker, which then completed the input. The probe exercises local control flow, not observed real broker delivery/loss.
8. Stop disposed the retained fake ServiceBusClient; a subsequent empty Start reported Started without replacing it. Registered-handler restart and network resource behavior remain source-based follow-up cases.

A positive two-page SDK fake also confirmed that Blob enumeration already traverses pages. These checks did not use credentials, Azure accounts, Azurite, live Service Bus, native Speech/GStreamer or other target runtimes. They establish local behavior, not provider parity, production incident frequency or released availability. No production fixes were made; proposed scopes are in [FEATURE-PROPOSALS.md](plan/FEATURE-PROPOSALS.md).
