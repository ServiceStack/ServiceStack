# ServiceStack.Aws features

Reviewed 2026-11-11 at source HEAD `101038b4ba5a65650e02491e98c7c8a4e1d46f5f` against implementation, tests and local framework documentation. This inventory distinguishes source presence, the limited validation below and confirmed released availability. Published-package availability was not cross-checked. AGENTS.md remains development guidance; implementation is the product-capability evidence.

## Package and ownership

- [ServiceStack.Aws.csproj](ServiceStack.Aws.csproj) targets `net472;net6.0;net8.0;net10.0`. It references ServiceStack, Client, Common, Interfaces and Text and AWS SDK v4 Core/DynamoDBv2/S3/SQS/TranscribeService packages. Additional async interfaces/LINQ/JSON dependencies vary by target.
- PocoDynamo and its public contracts belong to this package. AutoQuery Data integration adapts core ServiceStack query execution to DynamoDB; it is not a second SQL engine.
- S3/R2 storage, DynamoDB cache/auth/settings, SQS MQ and the Amazon Transcribe ISpeechToText provider are implemented here. The namespace `ServiceStack.AI` on AwsSpeechToText does not move its implementation to ServiceStack.AI.
- AWS/R2 credentials, endpoints and regions are supplied through SDK clients/factories and application configuration. S3 compatibility does not establish parity with every AWS operation or provider.
- Deployment recipes, RDS/OrmLite, SES examples, Lambda/ECS provisioning, Cloudflare AI services and infrastructure-as-code are not implementations of additional AWS adapters in this package. In particular, the project does not reference an SES SDK package.

## Validation and reproduced concerns

On 2026-11-11 all four library targets (`net472;net6.0;net8.0;net10.0`) and the net10.0 AWS test project built with existing warnings. After refreshing stale test dependency assets from the local NuGet cache, 33 existing credential-free net10.0 tests passed: AwsSecurityTests, FakeAmazonSqsTests and SqsQueueDefinitionTests. The two security methods were also invoked directly in a temporary runner. This did not exercise DynamoDB Local, live S3/R2/SQS/Transcribe, IAM, SDK credential discovery, production throttling or other target runtimes. No AWS account or resources were accessed by this review.

Six targeted net10.0 fake-client observations were reproduced against the built library:

1. A truncated synchronous S3 listing returned one page while async enumeration returned both scripted pages.
2. DeleteFolder("reports") sent both `reports/a.txt` and sibling `reports-archive/b.txt` to deletion when the fake modeled S3 prefix matching. Canonicalizing `..` does not make a raw string prefix a directory boundary.
3. Two coordinated AddAsync calls for the same absent DynamoDB cache key both returned true and issued unconditional PutItem requests.
4. PocoDynamo.ExecAsync repeatedly handled a cancelled task and ended with TimeoutException wrapping cancellation instead of preserving cancellation as terminal.
5. A partial SQS send failure invoked ErrorHandler after entries were removed from the pending buffer; the dispatch boolean was true and no failed entry remained buffered. This proves the observed callback/buffer semantics, not exactly which messages a real service accepted.
6. Supplied MessageGroupId/MessageDeduplicationId were absent from buffered SendMessageBatch entries. A filter or raw SDK property alone does not establish FIFO support in the high-level MQ path.

These observations motivate [AWS-001 through AWS-005](plan/FEATURE-PROPOSALS.md); no production fixes were made or accepted. Tests of the real provider limits, concurrent service behavior and supported SDK/target combinations remain necessary before release claims. The additional transaction/page/speech proposals are bounded source-based opportunities, not runtime-proven missing customer workflows.

## Catalog maintenance

- Consult implementation and this inventory before recommending a capability; a missing doc mention is not proof of missing behavior.
- Keep unaccepted ideas in [FEATURE-PROPOSALS.md](plan/FEATURE-PROPOSALS.md). Move a complete record to [FEATURE-IMPROVEMENTS.md](plan/FEATURE-IMPROVEMENTS.md) only after explicit acceptance, preserving its AWS-prefixed ID and agreed scope.
- Record source, validated behavior and released version independently. Update capability constraints and precise test evidence when behavior changes.
- Cross-project work has one canonical owner and participant links. Shared cache/MQ/VFS/auth/speech contracts must not acquire required members merely to expose an AWS-specific option.
- Keep architecture/security rules in [AGENTS.md](../../AGENTS.md); follow the [suite planning workflow](../../../ServiceStack/src/FEATURES.md#planning-workflow).
